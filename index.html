🌐 What is JavaScript, History & Alternatives

📖 Story: Imagine the web in 1995 was a static newspaper — you could only read it. Brendan Eich was hired by Netscape and, in just 10 days, created a scripting language to make pages interactive. It was first called Mocha, then LiveScript, then renamed JavaScript — purely as a marketing move to ride Java's hype.

Key Facts

  • Created: 1995 by Brendan Eich at Netscape
  • First names: Mocha → LiveScript → JavaScript
  • Standardised: ECMAScript (ECMA-262) by ECMA International
  • Paradigm: Multi-paradigm — OOP, functional, event-driven
  • Runtime: V8 (Chrome/Node), SpiderMonkey (Firefox)

Why JavaScript?

  • Only language natively run by browsers
  • Full-stack capability via Node.js
  • Huge ecosystem (npm > 2 million packages)
  • Non-blocking, event-driven & fast for I/O
  • Single language for frontend + backend

🔭 Scope, Scope Chain & Lexical Environment

📖 Imagine nested rooms inside a house. If you lose your keys in the inner bedroom, you look there first, then in the hallway, then the living room, then outside. That search path is the scope chain. The blueprint of which variables belong to which room — created at code-writing time — is the Lexical Environment.

Types of Scope

  • Global scope — accessible everywhere
  • Function scope — inside a function only
  • Block scope — inside {} (let/const)
  • Module scope — inside ES6 modules

Lexical Environment

Created at write-time. Contains:

  • Environment Record — actual variables & functions
  • Outer reference — link to parent scope

Scope chain is built by following these outer references.

let city = "Delhi";         // global

function country() {
  let state = "Rajasthan";  // function scope

  function village() {
    let area = "Jaipur";    // inner scope
    console.log(city);      // ✅ reaches global via scope chain
    console.log(state);     // ✅ reaches parent
    console.log(area);      // ✅ own scope
  }
  village();
  // console.log(area);     // ❌ ReferenceError
}

🏗️ Hoisting & Temporal Dead Zone (TDZ)

📖 Before your JavaScript code runs, the JS engine does a quick "pre-scan" — like a manager who walks through the office before work starts, noting where every desk (function/variable) will be, but not filling them yet. That pre-scan is hoisting. For let/const, the desk is noted but locked (TDZ) until the actual declaration line.

var hoisting

console.log(a); // undefined (hoisted)
var a = 5;
console.log(a); // 5

let/const — TDZ

console.log(b); // ❌ ReferenceError (TDZ)
let b = 10;
console.log(b); // 10
// Function declarations are fully hoisted
greet(); // ✅ Works!
function greet() { console.log("Hello"); }

// Function expressions are NOT
greet2(); // ❌ TypeError: greet2 is not a function
var greet2 = function() { console.log("Hi"); };
TDZ: The period between entering the block and the actual declaration line where let/const exist but cannot be accessed. Accessing them throws ReferenceError.

🔒 Mutability & Immutability

📖 A string is like a printed book — you can't erase a letter; you have to print a whole new book with the change. An object is like a whiteboard — you can erase and rewrite as much as you like on the same board.

Immutable — Primitives

let name = "Ram";
name[0] = "S";     // silent fail in non-strict
console.log(name); // "Ram" — unchanged!

// Strings are immutable in JS.
// Every operation returns a NEW string.
let upper = name.toUpperCase(); // "RAM"
console.log(name); // still "Ram"
Yes — strings are immutable. You cannot change a character in place. That is WHY name[0] = "S" silently does nothing.

Mutable — Objects/Arrays

const arr = [1, 2, 3];
arr.push(4);        // ✅ mutates in place
arr[0] = 99;        // ✅ mutates

const obj = { a: 1 };
obj.b = 2;          // ✅ mutates

// To make object immutable:
Object.freeze(obj);
obj.b = 99;         // silent fail
console.log(obj.b); // 2

⚙️ Operators: Ternary, Short-Circuit, Nullish, Optional Chaining

Ternary vs if-else

// if-else — use for complex multi-line logic
if (age >= 18) {
  console.log("Adult");
} else {
  console.log("Minor");
}

// Ternary — use for simple inline expression (returns a value)
const label = age >= 18 ? "Adult" : "Minor";

// ternary is an EXPRESSION (produces a value), if-else is a STATEMENT

Short-Circuit Evaluation

// && — stops at first FALSY
false && doSomething();   // doSomething never called
true && console.log("yes"); // "yes"
const name = user && user.name; // safe access
// || — stops at first TRUTHY
const val = input || "default";
// if input is falsy, use "default"

// ?? — Nullish coalescing
// ONLY null/undefined triggers fallback (not 0 or "")
const count = input ?? 0;
// if input is null/undefined → 0
// if input is 0 → 0 (preserved!)

Optional Chaining vs Ternary

// Without optional chaining → error if user is null
console.log(user.address.city); // ❌ TypeError if user is null

// With optional chaining (?.):
console.log(user?.address?.city); // undefined (no error)
console.log(user?.getName?.()); // calls method safely

// Ternary checks ONE condition and returns one of two values.
// Optional chaining (?.) short-circuits the whole chain if null/undefined.

First-Class Functions

Functions are first-class citizens in JS — they can be assigned to variables, passed as arguments, returned from other functions, just like any other value.

Pure Functions

// Pure: same input → same output, no side effects
function add(a, b) { return a + b; } // ✅ pure

// Impure: depends on external state
let count = 0;
function increment() { count++; } // ❌ impure — side effect

Higher-Order Functions

// A function that takes/returns a function
function multiplier(factor) {
  return function(num) { return num * factor; };
}
const double = multiplier(2);
double(5); // 10

// map, filter, reduce are all HOFs!

call, apply, bind

function greet(greeting, punct) {
  return `${greeting}, ${this.name}${punct}`;
}
const user = { name: "Arjun" };

greet.call(user, "Hello", "!");   // "Hello, Arjun!" — args spread
greet.apply(user, ["Hi", "?"]);   // "Hi, Arjun?" — args as array
const fn = greet.bind(user);      // returns new function with 'this' fixed
fn("Hey", ".");                   // "Hey, Arjun."

Variadic Functions & arguments

// Old way — arguments object (array-like, not real array)

  return [...arguments].reduce((a, b) => a + b, 0);
}

// Modern way — rest params (real array)
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3, 4); // 10

🔐 Closures

📖 Imagine you leave a sticky note on your fridge before going on vacation. Even when you're away (the function returned), the note is still there — the inner function remembers the variables of the outer function. That sticky note is a closure.
function makeCounter() {
  let count = 0;          // "sticky note"
  return {
    increment: () => ++count,
    decrement: () => --count,
    value: () => count
  };
}

const counter = makeCounter();
counter.increment(); // 1
counter.increment(); // 2
counter.decrement(); // 1
counter.value();     // 1
// count is private! can't access from outside.
Closures enable: data privacy, factory functions, memoization, module patterns.

🧬 Prototypes & Prototypal Inheritance

📖 Every object in JS has a hidden parent (prototype). If you ask an object for a property it doesn't have, it asks its parent, then grandparent — climbing the prototype chain until it hits null. Like inheriting family traits — no need to copy, just look up the family tree.
function Animal(name) {
  this.name = name;
}
Animal.prototype.speak = function() {
  return `${this.name} makes a sound.`;
};

const dog = new Animal("Dog");
dog.speak(); // "Dog makes a sound." — found on prototype, not dog itself

// Modern class syntax (syntactic sugar over prototypes)
class Vehicle {
  constructor(brand) { this.brand = brand; }
  honk() { return `${this.brand} goes beep!`; }
}
class Car extends Vehicle {
  drive() { return `${this.brand} drives.`; }
}
const c = new Car("Tesla");
c.honk(); // inherited from Vehicle.prototype

⚡ Synchronous vs Asynchronous

📖 Synchronous is like a single cashier at a counter — serve one customer, finish, then next. Asynchronous is like ordering food at a restaurant — you order (non-blocking), get a token, and the kitchen works while you sit. When ready, they call your token (callback/promise).

Synchronous

// Executes line by line, blocking
console.log("1");
// Heavy computation blocks here
console.log("2");
// Output: 1, 2

Asynchronous

console.log("1");
setTimeout(() => console.log("2"), 1000);
console.log("3");
// Output: 1, 3, 2
// "2" is non-blocking — JS moves on!

How JS Handles Async — Event Loop

JS is single-threaded but uses the Event Loop to handle async via:
Call Stack → Web APIs (setTimeout, fetch, DOM events) → Task Queue / Microtask Queue → Event Loop picks & pushes to stack 
// Phases order of execution:
// 1. Call Stack (sync code)
// 2. Microtask Queue (Promises .then, queueMicrotask)
// 3. Macrotask/Task Queue (setTimeout, setInterval, I/O)

console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// Output: A D C B
// C (microtask) runs before B (macrotask)!

📞 Callbacks → Promises → Evolution

📖 Callback: "Call me when you're done cooking!" You hand the chef a note (callback) and go watch TV. The problem: if the chef needs another chef who needs another chef — that's callback hell (Pyramid of Doom). Promises fixed this by saying: "I promise to return a result (or failure) — you can chain your next step."

Callback Hell

// Pyramid of doom — hard to read and maintain
loginUser(function(user) {
  getUserProfile(user.id, function(profile) {
    getUserPosts(profile.id, function(posts) {
      displayPosts(posts, function() {
        // 😱 getting deeper...
      });
    });
  });
});

Promises — Why they came

// A Promise has 3 states: pending → fulfilled | rejected

const fetchData = new Promise((resolve, reject) => {
  setTimeout(() => {
    const success = true;
    if (success) resolve({ data: "✅ result" });
    else reject(new Error("❌ Failed"));
  }, 1000);
});

fetchData
  .then(result => console.log(result))  // fulfilled
  .catch(err => console.error(err))     // rejected
  .finally(() => console.log("Done"));  // always runs

Promise Chaining

loginUser()
  .then(user => getUserProfile(user.id))
  .then(profile => getUserPosts(profile.id))
  .then(posts => displayPosts(posts))
  .catch(err => handleError(err));
// Flat and readable! 🎉

⏳ async / await — Why it came after Promises

📖 Even with promise chaining, you're still writing .then().then().then(). async/await (ES2017) made async code look synchronous — like reading a story left to right, top to bottom. Under the hood, it's still Promises.
// async function always returns a Promise
async function loadDashboard() {
  try {
    const user = await loginUser();         // waits here
    const profile = await getProfile(user.id); // then here
    const posts = await getPosts(profile.id);
    displayPosts(posts);
  } catch (err) {
    console.error("Error:", err.message);
  } finally {
    hideLoader();
  }
}

// Run multiple in parallel (don't await sequentially if independent!)
const [a, b] = await Promise.all([fetchA(), fetchB()]);
// Promise.all is FASTER than awaiting one by one

⏱️ Debouncing & Throttling

📖 Debounce: An elevator door — it waits until no one is pressing the button for X seconds before closing. Throttle: A machine gun with a rate limiter — no matter how fast you pull the trigger, it fires at most once per second.

Debounce — wait for pause

function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
// Use case: search bar — call API only after user stops typing
const search = debounce((query) => fetchResults(query), 500);

Throttle — limit rate

function throttle(fn, limit) {
  let lastCall = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastCall >= limit) {
      lastCall = now;
      fn.apply(this, args);
    }
  };
}
// Use case: scroll events, resize handlers
window.addEventListener("scroll", throttle(handleScroll, 200));

Node.js

JavaScript on the server — fast, event-driven, and non-blocking

🖥️ What is Node.js

📖 In 2009, Ryan Dahl was frustrated that Apache web servers blocked threads waiting for I/O (like a cashier freezing until the kitchen finishes). He took Chrome's V8 engine, wrapped it in C++ with libuv (an event loop library), and created Node.js — JavaScript outside the browser, with non-blocking I/O. The result: a single-threaded server that could handle thousands of concurrent connections.

Key Facts

  • Created: 2009 by Ryan Dahl
  • Engine: V8 (Google)
  • I/O: Non-blocking via libuv
  • Threading: Single-threaded event loop + thread pool
  • Package manager: npm (Node Package Manager)

Alternatives

  • Deno (Ryan Dahl again — fixes Node's regrets)
  • Bun (new, faster JS runtime)
  • Python (Django/Flask), Ruby (Rails), Go, Java

Features

  • Non-blocking, event-driven I/O
  • npm — world's largest package registry
  • Single language front+back
  • Streams for large data
  • Great for: REST APIs, real-time apps, microservices
  • NOT great for: CPU-heavy tasks

Architecture

Event Loop + Thread Pool: Node's main thread runs the event loop. For blocking I/O (file, DB), libuv uses a thread pool (4 threads by default). The result arrives via a callback back to the event loop — keeping the main thread free.

🔬 Aggregation Pipeline

📖 Think of aggregation as an assembly line. Each stage does one job and passes the result to the next. Raw documents go in, processed results come out. Stages are like stations: one filters, one groups, one sorts, one shapes the output.
db.orders.aggregate([
  // Stage 1: Filter
  { $match: { status: "completed", amount: { $gt: 100 } } },
  
  // Stage 2: Group and summarize
  { $group: {
    _id: "$customerId",
    totalSpent: { $sum: "$amount" },
    orderCount: { $count: {} },
    avgOrder: { $avg: "$amount" }
  }},
  
  // Stage 3: Add computed field
  { $addFields: { isHighValue: { $gt: ["$totalSpent", 1000] } }},
  
  // Stage 4: Sort
  { $sort: { totalSpent: -1 } },
  
  // Stage 5: Limit
  { $limit: 10 },
  
  // Stage 6: Shape output
  { $project: { customerId: "$_id", totalSpent: 1, orderCount: 1, _id: 0 }},
  
  // Stage 7: Lookup (JOIN)
  { $lookup: {
    from: "customers",          // join with customers collection
    localField: "customerId",
    foreignField: "_id",
    as: "customerInfo"
  }},
  
  // Stage 8: Write to new collection
  { $out: "top_customers" }     // creates/replaces collection
]);

// $expr — use aggregation expressions in $match
db.orders.find({ $expr: { $gt: ["$amount", "$budget"] } })

// $cond — conditional (like ternary)
{ $cond: { if: { $gt: ["$score", 90] }, then: "A", else: "B" } }

// $facet — multiple pipelines in one query
{ $facet: {
  byStatus: [{ $group: { _id: "$status", count: { $sum: 1 } } }],
  byCity: [{ $group: { _id: "$city", count: { $sum: 1 } } }]
}}

// $bucket — group into ranges
{ $bucket: {
  groupBy: "$age",
  boundaries: [0, 18, 30, 60, 100],
  default: "other",
  output: { count: { $sum: 1 } }
}}

🗂️ Indexes — Types, Testing & Management

📖 An index is like a book's table of contents. Without it, MongoDB reads every page (collection scan = COLLSCAN). With an index, it jumps directly to the right page (IXSCAN). Creating the right index is the #1 performance optimization in MongoDB.
// Create indexes
db.users.createIndex({ name: 1 })               // ascending
db.users.createIndex({ name: -1 })              // descending
db.users.createIndex({ email: 1 }, { unique: true }) // unique index
db.users.createIndex({ name: 1, age: -1 })      // compound index
db.users.createIndex({ bio: "text" })           // text index (full-text search)
db.users.createIndex({ createdAt: 1 }, { expireAfterSeconds: 86400 }) // TTL index
db.users.createIndex({ location: "2dsphere" })  // geo index
db.users.createIndex({ tags: 1 })               // multikey (array) index

// Wildcard index — index all fields
db.users.createIndex({ "$**": 1 })

// List indexes
db.users.getIndexes()

// Delete an index
db.users.dropIndex("name_1")
db.users.dropIndex({ name: 1 })
db.users.dropIndexes() // drop ALL (except _id)

// Test if index is working:
db.users.find({ name: "Arjun" }).explain("executionStats")
// Look for: winningPlan.stage = "IXSCAN" ✅ (not COLLSCAN ❌)
// totalDocsExamined should be close to totalDocsReturned for efficiency

// Capped Collection — fixed-size, auto-oldest-removal (like a circular buffer)
db.createCollection("logs", { capped: true, size: 1000000, max: 1000 })
// Great for: logs, activity feeds, real-time event streams

// TTL Index — auto-delete documents after time expires
db.sessions.createIndex({ createdAt: 1 }, { expireAfterSeconds: 3600 }) // delete after 1 hour

🏗️ Schema Design, Embedding vs Referencing

📖 Embedding = put related data inside the same document (like keeping your passport in your travel bag — always together). Referencing = store a link (ObjectId) to another document (like a library card that points to a book on a different shelf — join needed to get it).

const listUsers = async ({ search, sort, page = 1, limit = 10 }) => {
  const query = {};
  if (search) {
    query.$or = [
      { name: new RegExp(search, 'i') },
      { email: new RegExp(search, 'i') }
    ];
  }
  const sortOption = {};
  if (sort === 'asc') sortOption.name = 1;
  else if (sort === 'desc') sortOption.name = -1;
  
  const skip = (page - 1) * limit;
  const users = await User.find(query).sort(sortOption).skip(skip).limit(limit);
  const total = await User.countDocuments(query);
  return { users, total, pages: Math.ceil(total / limit) };
};
